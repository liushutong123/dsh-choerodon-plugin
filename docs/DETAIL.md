# 猪齿鱼（Choerodon）

把猪齿鱼的账号、项目上下文、任务看板、评论与项目模型接进 DeepSeek Harness。

## 界面

样式全部是插件自带的 CSS（约 17 KB 规则），不用任何 UI 库、不引 CDN、不联网取样式：

- 颜色与圆角全部落在 DSH 的主题变量（`--dsw-alias-*`）上，**深浅色自动跟随宿主**，不再写死深色。
- 按钮、输入框、标签有 hover / active / focus-visible 三态与 120ms 过渡；
  之前是纯内联 style，hover 和键盘焦点都没有反应，这是「按钮看着不好看」的根因。
- 尊重 `prefers-reduced-motion`：开启减少动效时，过渡与动画全部关掉。
- 样式表在 `apply` 里挂一次，插件卸载时随 `ctx.effect` 一起收回，不会残留。

## 能做什么

- 左侧栏「猪齿鱼」入口，面板分两个标签页：
  - **模型接入**：登录、切换组织与项目、把项目模型写进 DSH 的模型选择器。
  - **任务看板**：按状态分泳道展示工作项，默认只看「我的」，也可以看全部；可以新建任务。
- 看板工具栏：
  - **我的 / 全部**：默认「我的」，切到「全部」就能看别人的单，进来不会默认看到一堆别人的任务。
  - **史诗筛选**、**经办人筛选**：都是多选下拉，支持搜索，勾选即重查；泳道上的数字是过滤后的真实总数。
    明确勾了经办人时以筛选为准，比如只勾同事就只看同事的，不再叠加「我的」。
  - **新建任务**：填概要、类型、优先级、经办人、工时、计划、描述，直接建成一条工作项。
- 卡片详情分**五个页签**（右上角 ✕ 关闭），每页只装一类内容，切到哪页才拉哪页的数据：
  1. **详情**：状态、经办人、优先级、史诗、计划、工时汇总、**附件**、可流转状态、描述，
     以及底部的「创建工作分支 / 复制为一条新任务（或复制并打开）」。
  2. **依赖与关联**：子任务（带快捷创建）、关联工作项（按「复制 / 被复制」方向分组）、模块与版本。
     子任务和关联里的编号都能点开，直接跳到那条工作项的详情。
  3. **工时**：工时日志的条数与合计、逐条流水（耗费小时、工作日期、说明、登记人、可删），
     顶部「登记工时」展开表单（耗费时间、工作日期、描述、剩余预估四档）。
  4. **评论**：评论列表（含回复）与发表框；正文写 `@姓名` 会转成平台提及。
  5. **操作记录**：谁在什么时候把哪个字段从什么改成了什么。顶部单独一块「经办人变更」，
     直接写明「某人 把经办人从 X → Y」，改完要分回给谁一眼就能看到。
- 卡片详情主体：
  - 工作项描述（富文本转纯文本，描述里的图片按缩略图展示，可点开）、状态、经办人、史诗、计划、工时。
  - **改经办人**：从项目成员里挑一个立即改过去，或「改为我」，或清空经办人。不用回网页点。
    成员用带搜索的浮层挑，和看板筛经办人同一个控件：默认只列前 10 条，输入**姓名或工号**就地筛。
  - **评论**：抽屉里直接读评论（含回复、附件）并发表新评论；正文写 `@姓名` 会转成平台的提及。
  - **改工时**：原始预估与剩余预估（小时）。
  - **登记工时**：和工作项详情里的「工时日志」页同一个接口。填耗费时间、工作日期、描述，
    剩余预估按网页端的四种口径处理（自动调整 / 不调整 / 设置为 / 缩减）；下面直接列出已登记的流水，
    合计小时数，单条可以删。登记完看板与工作项会一起刷新。
  - **可流转状态**：点一下就切过去；工作项已经建过会话时显示「已绑会话」，一键跳过去。
  - **复制为一条新任务**：按当前单复制一份，描述、优先级、经办人、史诗、预估/剩余工时、计划都抄过来，
    描述里注明来源单。
  - **创建工作分支**，两种开发方式：
    - **新建分支**：分支名固定为 `feature-<编号>` 或 `bugfix-<编号>`，例如 `bugfix-PROJ-456`。
      - 分支不存在：先切到来源分支并 `fetch` + `pull --ff-only`，再 `git worktree add -b`。
      - 分支已存在：直接复用它挂成 worktree，**不做任何合并**；只统计它比来源分支落后多少提交。
    - **固定分支（就地开发）**：选一个已经检出的分支（默认当前分支），直接用该分支的工作目录开会话。
      **不新建分支、不建 worktree、不动任何 Git 引用**，全程只读（`rev-parse`、`worktree list`）。
  - 建会话弹窗里先选**经办人怎么处理**：
    - **保持原经办人**（默认）：谁的单就还是谁的，未分配的也保持未分配；
    - **改为我**：把单认领到自己名下；
    - **指定的人**：从项目成员里选一个改过去。成员用带搜索的浮层挑（和看板筛经办人是同一个）：
      默认只列前 10 条，上面输入**姓名或工号**就地筛，几百人的项目也不用在一长串里翻。
    另外可以取消「同时把状态推进到开发中」，只建会话不动状态。
  - 目录在**主仓库目录下**的 `.worktrees/<分支名>`（仅新建分支模式）。
  - 上下文写进 `<仓库>/.dsh/choerodon/<编号>.md`，同时给会话注入一份精简要点。
  - 创建完成后**自动在仓库目录建会话**，标题 `PROJ-xxxx 问题摘要`，工作目录指向该 worktree，
    并把这个会话登记进仓库对应的工作区，弹窗关掉时直接选中它。
  - 会话走的是侧栏「新建对话」同一条创建路径（`sessionController.create`），所以**工具与权限和手动新建的
    会话完全一致**：preset 的插件树（`read`/`write`/`edit`/`pwsh`/`glob`/`grep`、技能目录、persona）都会挂上，
    默认模型也由宿主注入，不会出现「插件建的会话改不了文件」。
  - 工作项全文（编号、状态、经办人、计划、分支、目录、描述正文与图片链接）在建会话时**填进输入框草稿**：
    走会话自己的输入门面 `conversation.input.requestDraftInitialization`（和「点推荐提示词开新会话」同一条路），
    草稿里已有内容时保留不动。填草稿由**建会话那一步**触发，不挂在会话头组件上——
    空白会话首页根本不渲染会话头，挂上去就会变成「开进去是空的、发完第一条才冒出来」。
    绑定没就绪时每 200ms 重试，最多约 10 秒，期间会话一旦不再空白就放弃、绝不在对话开始后补。
    人可以照着看、改一句、甚至整段换成自己的说法再发，
    模型拿到的就是把关过的那份文本——不再由 Host 先 inject 一条用户消息。
  - 会话在发出第一条消息之前日志里没有可展示的节点（首条 `system/message` 与用户消息都由第一个回合写入），
    所以这份文本只能先放在输入框里。会话头右上角另有一个「本次工作项」入口（`/choerodon/session-brief`），
    点开是同一份原文，方便发出去之后再对照。界面填不进去（会话没在前台、输入框正在提交）时，
    客户端才调 `/choerodon/session-context` 让 Host 兜底 inject 一次，避免模型连任务描述都没见过。
- 模型以 `choerodon-` 前缀出现在 DSH 模型选择器里，例如
  `choerodon-DeepSeek-V4.1-Flash-1017`、`choerodon-GLM5.3`。

## 有新任务时会提醒

插件每 60 秒查一次「有没有人把新单分给我」：

- 侧栏「猪齿鱼」那一行末尾出现红色角标 `n`，悬浮时显示条数；侧栏收起时是图标右上角的小红点。
- 打开面板时顶部出现一条提示：**有新任务（n）**，带前几条的编号，可以点「去看板」或「全部已知」。
- `n` 是「经办人是我、且不是我上次见过的」工作项条数。它**会跳跃**：确认过一批、或者别人把单收回去，
  数字就会变小甚至归零；新分来一条，它就加一。
- 检测口径是「我名下所有工作项」的 id 集合，所以别人把一张很早创建的老单改派给我，也会被算成新任务。
- 点「全部已知」后这批单并入基线，角标清零；也可以让模型调 `choerodon_inbox` 带 `acknowledge: true`。

站内消息未读数（网页右上角铃铛）也在同一次请求里带回来；那个服务在部分环境里没装，
读不到就按 0 处理，不影响角标。

## 给模型的工具

| 工具 | 用途 |
|---|---|
| `choerodon_board` | 按泳道读取任务看板，`mine` 默认 true 只看自己经办的，给 false 看全部；`epic`/`assignee` 按名称包含匹配（逗号分隔多个），`epicIds`/`assigneeIds` 按 id 精确筛选；条目带 `epic`/`sprint`/`estimateTime` |
| `choerodon_issue` | 读取单个工作项的详情与可流转状态，支持传工作项编号如 `PROJ-123` |
| `choerodon_comment` | 不传 `body` 读评论（含回复、附件），传 `body` 发评论；`markdown` 做格式转换，`mention` 指定要 @ 的人 |
| `choerodon_create_issue` | 建工作项；给 `copyFrom` 就是按现有工作项复制一份 |
| `choerodon_estimate` | 改原始预估 / 剩余预估工时（小时） |
| `choerodon_worklog` | 登记或查看工时日志：给 `workTime` 就是登记一条，不给就读已有流水与合计；`residualPrediction` 选剩余预估口径 |
| `choerodon_activity` | 读操作记录：谁在什么时候把什么字段从什么改成什么；单独给 `assignees` 列出经办人变更，用来回答「这张单现在归谁、是谁分的」 |
| `choerodon_inbox` | 看站内未读数与「新分给我的任务」；`acknowledge: true` 把当前这批并入已知、角标清零 |
| `choerodon_update` | 改状态（必须在可流转状态里，如 `开发中`、`待测试`、`已完成`）或改经办人（姓名、工号、用户 id 或 me），`clearAssignee` 清空；流转到需要审批的状态时可带 `comment` |
| `choerodon_worktree` | 按工作项创建 worktree 与分支，返回可直接使用的目录 |

会话里直接说「置为待测试」「把这条转给叶红柳」「在这条下面留个评论说已经修了」，模型就会调对应工具。

## 怎么用

1. 打开左侧「猪齿鱼」，在**模型接入**里登录：账号密码、浏览器授权、粘贴 `access_token` 三选一。
   密码只用于本次换取 token，不落盘。
2. 选择组织与项目，点「刷新并接入模型」。插件会在该项目下复用一个名为 `DSH 模型代理` 的常驻会话，
   然后把模型写进 DSH。
3. 切到**任务看板**：默认只看「我的」；点卡片看详情，勾筛选精确定位。
4. 建分支弹窗里选仓库。两种来源：
   - 点「选择目录…」用系统的目录选择器挑一个 Git 仓库；
   - 或在看板顶部填路径再点「设为仓库」。
   无论哪种，插件都会把这个目录**登记成 DSH 工作区**。
5. 建会话时选好经办人怎么处理、要不要推进状态，再点「创建分支、上下文与会话」。

## 文档落位

`docs/` 下按 `NN-主题` 分目录。插件会读出已有主题目录，用工作项摘要做最长公共子串匹配选一个
（要求重合至少 3 个字，避免「预算」这种两字词误吸），匹配不到就落到 `docs/90-其他`。
弹窗里可以手动改：下拉选已有目录，或直接输入 `docs/NN-新主题`。

## 需要知道的限制

- 猪齿鱼的模型接口是**会话级**的：路径里带 `conversations/{id}`，所以每个「组织 + 项目」会复用
  一个代理会话，它会出现在猪齿鱼网页端的会话列表里。
- 登录用 OAuth 隐式流，没有 refresh token：过期后需要重新登录，插件会在调用时提示。
- 看板列接口（`board/columns`）对该账号返回 403，所以泳道顺序是插件按生命周期排的。
- 只接入 `OPENAI` 与 `ANTHROPIC` 两种协议的项目模型；其它协议会被跳过。
- **工时**分两层：工作项上的「原始预估 / 剩余预估」是汇总字段，走 `PUT issues`；
  「工时日志」是流水，走敏捷服务的 `/work_log`（`GET .../work_log/issue/{id}` 读、
  `POST .../work_log` 建、`DELETE .../work_log/{logId}` 删）。插件两套都支持，登记流水时
  剩余预估的口径由平台按 `residualPrediction` 自己落。
- **删除**：工作项与工时日志都能删。工作项走 `DELETE /issues/{issueId}`（204，不需要 `source`），
  因不可撤销，工具层要求 `confirm: true`；工时日志走 `DELETE /work_log/{logId}`。评论删除没有提供，回网页删。
- 优先级列表接口对该账号返回 404，只能用 `priority/default`，所以新建任务时优先级只有一个默认项。
- 状态文件位于 `$DSH_HOME/choerodon-harness/state.json`（权限 0600），保存登录凭据与设备身份。

## 版本自检（重要）

这个插件在开发机上常用 **Junction（目录联接）/ link 依赖** 的方式装，指向源码目录：

- **client.js**：浏览器每次刷新都会从磁盘重读，改完刷页面就生效。
- **index.js（Host 半区）**：只在 DSH 进程启动时加载一次，改完必须**重启 DSH**。

所以会出现「界面是新的、接口还是旧的」：登记工时点下去报 404、操作记录打不开、角标不出现。
插件对此做了两道提示：

1. 面板顶部直接显示「插件版本不匹配」，写清宿主版本和「重启 DSH 才会工作」。
2. 任何接口 404 都会提示「宿主没有这条接口，重启一次 DSH」，而不是只甩一句 HTTP 404。

`GET /state` 的 `host` 字段给出 `{ version, features, startedAt }`，可用来核对进程里到底是哪一版：
`features` 含 `worklog`、`activity`、`inbox` 就说明新宿主已经起来了。
## 从通知点进一张单的边界情况

「有新任务」横幅里每条工作项都是可点的，点一下直接打开那条的详情。点进去时可能已经变样，插件分三种情况处理：

| 情况 | 表现 |
|---|---|
| 一切正常 | 正常打开详情抽屉 |
| **单已被删除 / 没权限** | 不开抽屉，顶部一条红字：「这张工作项已经没了」，附「刷新看板」「知道了」两个按钮。平台对删除没有专用错误码，靠 404 + 文案识别 |
| **单已改派给别人** | 照常能看详情，但顶部一条提醒：「这张单已经不在你名下了，现在经办人是 XXX」，并给「改为看全部」按钮。关掉抽屉后它确实不在「我的」看板里，这是平台的真实行为，插件不假装它还在 |

接口 404 也做了区分：只有宿主返回「未知接口」才提示「重启 DSH」，
其它 404（工作项已删除、没权限）按业务失败原样报出，不会误导人去重启。
## 本轮补的接口（都实测过）

| 能力 | 接口 | 关键点 |
|---|---|---|
| 附件上传并挂到工作项 | `POST /issue_attachment`（multipart） | 一次搞定。`bucketName` 必须是 `agile-service`，传成别的会报 OBS 上传失败；`issueId` 用表单字段或 query 都行 |
| 附件删除 | `DELETE /issue_attachment/{attachmentId}` | 204，无响应体 |
| 关联工作项读 | `GET /issue_links/{issueId}` | 返回数组，每条自带 `ward`（复制 / 被复制 / 阻塞…）表示相对当前单的方向 |
| 关联工作项写 | `POST /issue_links/{issueId}` | **body 必须是数组**，且每条要带 `linkTypeId`；传对象会 400 |
| 关联删除 | `DELETE /issue_links/{linkId}` | 204 |
| 子任务创建 | `POST /issues?applyType=agile` | 父单字段是 **`parentIssueId`**，不是 `parentId`（传 `parentId` 会被静默忽略，建出来是个游离单）；必须带 `typeCode` 和 `priorityId`。项目的 sub_task 会拆成「前端开发任务 / 后端开发任务 / 测试子任务」等变体，只按编码取第一个会永远建成非开发子任务，所以按 `issueTypeId` 选类型，`typeCode` 跟着选中类型走 |

几个踩过的坑，代码里也留了注释：

- **雪花 id 一律用字符串传**。`priorityId` 是 64 位，转 `Number` 会丢精度，服务端直接回「优先级ID为空或不合法」。
- 工作项类型清单里编码字段叫 `typeCode`，不是 `code`。
- 详情接口本身就返回 `issueAttachmentVOList` / `subIssueVOList` / `versionIssueRelVOList` /
  `componentIssueRelVOList`，不用另外打接口；只有关联工作项要单独查一次 `issue_links`。
- 一些看起来该有的接口在本环境是 404（`issue_link_types`、`versions`、`components`、`sprints` 等），
  所以关联类型没有做成可选项，而是沿用已有关联的 `linkTypeId`。

## v0.8.0 / v0.9.0：搜索、字典、字段更新、附件下载与性能

### 新增接口（全部实测通过）

| 能力 | 接口 | 约束 |
|---|---|---|
| 搜索 | `POST /agile/v2/projects/{p}/issues/work_list` + `content` LIKE | `fieldType:'input'`，值放 `value.valueStr` |
| 模块目录 | `GET /agile/v1/projects/{p}/component?organizationId=` | 26 个模块；`component/query_all` 报程序错误 |
| 标签目录 | `GET /agile/v1/projects/{p}/issue_labels?organizationId=` | 该项目当期为空 |
| 改字段 | `PUT /agile/v1/projects/{p}/issues` | 不能带 `projectId`；关系字段是 `componentIssueRelVOList` |
| 转类型 | `PUT|POST /issues/update_type` | 本环境两种方法都失败，工具返回 `available:false` |

### 两个真 bug

1. `issueTypes()` 在类里定义了两次，后者覆盖前者且字段名写成 `code`，
   导致 `createIssue` 的 `body.typeCode` 是 `undefined`、按 `typeCode` 指定类型也匹配不到。
2. `createIssue` 残留 `body.parentId`；平台字段是 `parentIssueId`，传错会被静默忽略、建出游离单。

### 状态发现：采样不够，必须全量 + 硬判据

平台没有状态目录接口（`query_status` / `status/list` / `issue_status` / `query_all_status` 全是 404 或程序错误），
状态只能从工作项样本反推。采样多少都不够：30 页（1.5 万条）仍会漏掉「设计评审」；
全量翻 247 页（12.3 万条）约 104 秒，能拿全 25 个状态。

判据必须是硬的：**Σ(各状态 count) == work_list 的 totalElements**。
实测 25 个状态合计 123053，与平台总数完全一致；漏掉「处理中」（83 条）或「DEV-已完成」（594 条）时立刻对不上。
容差取 `max(5, total×0.1%)`，因为判据是「先取总数、再逐状态计数」，两次测量之间的并发变动不该被当成漏状态。

于是做成两层：
- **快路径**：累积缓存 + 3 页采样，立刻出泳道（约 0.8s），不让人等 100 秒；
- **后台补全**：全量扫描通过判据后写缓存并标 `complete`，`/notifications` 带 `statusCompleted` 标记，
  前端看到就自动重拉一次看板。

### 三个把泳道弄丢的 bug

1. **数组引用被就地抽干**：`board()` 把 `discoverStatuses()` 返回的数组直接当队列 `shift()`，
   而缓存命中时返回的就是 `cache.statuses` 本身 —— 第一次打开正常，第二次变 0 条泳道，
   而且每次都退回慢路径。修法是返回值与队列都复制一份。
2. **强制刷新反而丢泳道**：`force` 曾把累积底稿丢掉，刷新后只剩快路径采样到的 21 条。
   现在 force 只重探平台，不丢底稿。
3. **空泳道优化误杀**：曾用「最近 200 条的状态分布」决定跳过哪些泳道，低频状态被判成 0 条，
   实际 `DEV-已完成` 有 594 条。现在只判「有没有候选单」，0 条由查询本身给出。

### 附件存储与下载

上传走 `POST /agile/v1/projects/{p}/issue_attachment`（multipart，`bucketName=agile-service`），
服务端落华为云 OBS 私有桶（桶名按租户分配），对象键形如
`agile-service/<租户>/<桶域>/<工作项散列>/<文件名>`。匿名访问 403。

下载的正确链路（抓包 + 实测确认）：

1. `GET /hfle/v1/files/redirect-url?bucketName=private&url=<附件原始OBS地址>` → **302**
2. `Location` 是 OBS 预签名地址（`AccessKeyId` / `Expires` / `Signature`）
3. 跟随该地址 → **200**，拿到原文件字节

实测：`sub-127060-borrow-link2.png` 141732 字节，与附件元数据 `size` 一致。
三个参数要点：`bucketName` 必须 `private`；路径必须连字符 `redirect-url`；
`url` 必须是原始 OBS 地址（传 `fileKey` 会 `NoSuchKey`）。

面板把它包装成 `GET /choerodon/attachment/url` 与工具 `choerodon_attachment_url`。

### 删除工作项

`DELETE /agile/v1/projects/{p}/issues/{issueId}` → **204**，条目真的消失（再读详情 404）。
不需要 `source` 参数；三种写法都验证过（无参 / `?source=agile` / `?source=backlog`）。
偶发 `source cannot be null` 是平台校验抖动，重试有效。旧结论「删不掉 / 需要 source」是错的。
因为不可撤销，插件层要求 `confirm: true` 才执行，并回读确认确实删掉了。
